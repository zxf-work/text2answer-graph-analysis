    How it works

    You give the system an edge-list file and a question in plain language. The language model never sees the graph. It sees a profile card: statistics the system computed from the file (is each edge listed once or in both directions, is there a header, which column looks like a weight, are there repeated rows), with the semantics it inferred and its confidence.

    From the card and your question the model writes a typed plan: a small dataflow of operators from a fixed catalogue (degree, shortest path, communities, betweenness, ...). The plan is validated against the catalogue's types, its cost is estimated, and expensive steps are switched to approximate tiers when the graph is large. Then the plan is executed, not the model's prose.

    A verifier checks the result without knowing the right answer: invariants (a partition covers every node, PageRank sums to one), agreement between methods, and consistency between your question, the stated interpretation and the plan ("you asked for followers, the plan used out-degree"). When the question is genuinely ambiguous the system asks you instead of guessing.

    The Tool agent and Code generation tabs run the same question through two conventional baselines, so you can compare what they return and what they cannot show you.
